`AUTH_SECRET` の新しい値を生成して設定する方法について、具体的な手順を解説します。

開発環境外すとローカルで作業できなくなる問題は?

--------------------------------------------------------------------------------

そうですよね、まさにそこが一番気になるポイントだと思います！[Vercel] の画面で 「Development」のチェックを外すと、一見ローカル環境で動かなくなりそうに見えますが、**まったく問題ありませんので安心してください。**

これには開発のセオリーに基づいた明確な理由と、正しい解決策があります。

なぜ外しても大丈夫なのか？

[Vercel] の画面にある「Development」というチェックボックスは、**vercel dev コマンドなどを使って、Vercelのクラウド上からローカル環境へ直接環境変数を同期（ダウンロード）してくる機能**を使うかどうかの設定です。

しかし、セキュリティの原則として、**「本番環境やプレビュー環境で使う本物の鍵（本物のシークレット）」をローカル環境でそのまま使うべきではない**というルールがあります。もしローカルで本物の鍵を使っていると、開発中のミスで本番データを書き換えてしまったり、開発中のエラーログから鍵が漏洩したりするリスクがあるからです。

そのため、Vercelは「本番用の大切なシークレット（Sensitive）をローカルに同期させるのは危ないから、チェックを外してね」と警告してくれているわけです。

ローカルで作業を続けるための正しい手順

ローカル環境（[Macbook Pro]）での作業を止めずに、かつ安全に開発を続けるには、「ローカル専用の仮の鍵」を手元のファイルに用意します。

手順1：Vercel側ではチェックを外して保存する

前述の通り、[Vercel] のダッシュボード上では「Development」のチェックを外し、`Production` と `Preview` だけにチェックを入れた状態で、変数を「Sensitive」として保存します。これでクラウド側の安全は確保されます。

手順2：ローカルの .env.local ファイルに書き込む

あなたのPC内にあるプロジェクトのルートディレクトリ（一番上の階層）に、**.env.local** というファイルがあるか確認してください。なければ作成します。

そのファイルの中に、ローカル開発専用の値を直接記述します。 Plaintext

```
# .env.local の中身

# Googleのシークレット（本番用とは別の、ローカルテスト用のID/シークレットを使うのが理想です）
AUTH_GOOGLE_SECRET=あなたのローカル用Googleシークレット

# AUTH_SECRETはローカル専用にその場で適当に作った文字列でOKです
AUTH_SECRET=local_development_secret_string_12345

```

なぜこれで動くのか？

Next.js などのフレームワークは、ローカルで起動（`npm run dev` など）した際、Vercelのクラウドではなく、まず手元の **.env.local** ファイルに書かれた環境変数を最優先で読み込みます。

そのため、Vercel側の「Development」のチェックを外して同期を切ったとしても、手元の `.env.local` に値が書いてあれば、ローカルでの作業はこれまで通りまったく問題なく実行可能です。

まとめ

1. Vercel上： 「Development」を外して本番用の値を Sensitive で安全に保存する。
2. 手元のPC内： .env.local ファイルにローカル用の環境変数を書いて開発する（このファイルは [GitHub] などの公開リポジトリには絶対にコミットしないよう .gitignore に含めておきます）。

この切り分けを行うのが、現代のWeb開発における標準的で安全なやり方になります！

これで、本番環境のセキュリティを守りつつ、ローカルでの作業環境も維持することができます。少し手順が多いですが、上から順番に進めてみてください！

💡 入力する内容（結論）

- ローカル開発環境用： http://localhost:3000/api/auth/callback/google

ステップ1：「承認済みの JavaScript 生成元」を設定する

1. 「承認済みの JavaScript 生成元」の下にある 「＋ URI を追加」 ボタンをクリックします。
